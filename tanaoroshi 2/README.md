# バーコード読取式 棚卸しシステム

商品のバーコードをスマートフォン/タブレットのカメラで読み取り、商品情報を自動表示、
棚卸実数を入力するだけで棚卸しが完了するWebアプリケーションです。
設計の詳細は [`DESIGN.md`](./DESIGN.md) を参照してください（ER図・画面遷移図・API仕様）。

データベースはPostgreSQL(Neonの無料枠を利用)を使用する構成になっています。
本README「3. クラウドへのデプロイ手順」の通りに進めれば、月額費用0円でスマホから
アクセスできる状態まで公開できます。**アプリ本体はクラウド上で常時稼働するため、
店内のPCの電源を入れっぱなしにしておく必要はありません。**

## 1. 動作環境

* Node.js 18以上
* PostgreSQL（本番はNeonの無料枠、ローカル動作確認用には手元のPostgreSQLでも可）
* モダンブラウザ（スマホ: Chrome/Safari、PC: Chrome/Edge等）
* カメラでのバーコード読取には **HTTPS接続**（またはlocalhost）が必要です

## 2. ローカルでの動作確認（任意）

手元のPCでPostgreSQLが使える場合のみ、次のように起動できます。

```bash
npm install
cp .env.example .env        # .env の DATABASE_URL に接続先を記入
npm run seed                 # 部門・サンプル商品マスターを投入（初回のみ）
npm start                     # http://localhost:3000
```

手元にPostgreSQLがない場合は、この手順は飛ばして次章のクラウドデプロイに進んでも問題ありません。

## 3. クラウドへのデプロイ手順（GitHub不要の方向け・月額0円構成）

**Neon（データベース）とRender（アプリ本体）を使い、実際にスマホからアクセスできる状態にします。**
所要時間の目安は20〜30分です。GitHubアカウントをお持ちでない前提で、作成手順から説明します。

### ステップ1: GitHubアカウントを作成する

1. [github.com](https://github.com/) にアクセスし、「Sign up」からアカウントを作成します（メールアドレスと任意のパスワードでOK、無料）。

### ステップ2: GitHubにコードを置く（リポジトリ作成）

1. ログイン後、右上の「＋」→「New repository」を選択します。
2. Repository name に `tanaoroshi-system` などの名前を入力し、Public/Privateどちらでも構いません（Privateでも次のRender連携は可能です）。「Create repository」をクリックします。
3. 作成されたリポジトリ画面の「uploading an existing file」というリンクをクリックします。
4. お渡ししたフォルダの中身一式（`server`フォルダ、`public`フォルダ、`package.json`など）を、フォルダごとまとめてブラウザの画面にドラッグ＆ドロップします（`node_modules`フォルダはそもそも同梱していないのでそのままで大丈夫です）。
5. 画面下部の「Commit changes」をクリックしてアップロードを確定します。

### ステップ3: Neonでデータベースを作成する

1. [neon.tech](https://neon.tech/) にアクセスし、「Sign up」からアカウントを作成します（GitHubアカウントでログインすると手早く進められます）。
2. 「Create a project」からプロジェクトを作成します（リージョンは日本から近い `Asia Pacific (Tokyo/Singapore)` 系があれば選択、なければそのままで問題ありません）。
3. 作成後の画面（Connection Details）に表示される接続文字列（`postgres://...neon.tech/...` の形式）をコピーします。この文字列は後でRenderに設定するので、メモ帳などに一時的に貼り付けておいてください。

### ステップ4: Renderにアプリをデプロイする

1. [render.com](https://render.com/) にアクセスし、GitHubアカウントでサインアップします。
2. ダッシュボードの「New +」→「Web Service」を選択します。
3. 先ほど作成した `tanaoroshi-system` リポジトリを選択して「Connect」します。
4. 設定画面で以下を入力します。
   - **Name**: 任意（例: tanaoroshi-system）
   - **Region**: Singapore など日本に近いリージョン
   - **Branch**: main
   - **Build Command**: `npm install && node server/seed.js`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
   - ※ `Build Command` に `node server/seed.js` を含めているのは、部門とサンプル商品マスターの初期データを自動投入するためです。Renderの無料プランには「Shell」機能（コマンドを直接実行する機能）がなく、npm run seed を手動実行できないため、この方法で対応しています。このコマンドは何度実行してもデータが重複したり壊れたりしない作りなので、以後デプロイのたびに実行されても問題ありません。
5. 「Advanced」を開き、「Add Environment Variable」から以下を追加します。
   - **Key**: `DATABASE_URL` / **Value**: ステップ3でコピーしたNeonの接続文字列
6. 「Create Web Service」をクリックするとビルド・デプロイが始まります（数分かかります）。
7. デプロイ完了後、`https://（アプリ名）.onrender.com` のようなURLが発行されます。このURLにスマホからアクセスすれば、カメラでのバーコード読取まで含めてそのまま使えます。アプリのURLを開いて「商品検索」画面でサンプル商品が表示されれば、初期データ投入も成功しています。サンプルデータは削除して、実際の商品マスターをCSV/Excel一括登録から投入してください（本README「6. 商品マスターの一括登録」参照）。

**うまくいかない場合の確認ポイント**

* ビルドログに `npm error ... no such file or directory` のようなエラーが出る場合、GitHubへのアップロード時にフォルダが一段余分に入れ子になっている可能性があります。GitHubのリポジトリ画面で `package.json` が最上位にあるかを確認し、`tanaoroshi` のようなフォルダの中に入っている場合は、Renderの「Settings」→「Build & Deploy」にある「Root Directory」欄に、そのフォルダの名前を**GitHub上の表示と完全に一致させて**（大文字小文字・スペースも含めて）入力してください。

### 補足: 無料プランの制約について

RenderのFreeプランは15分間アクセスがないと自動でスリープし、次のアクセス時に起動まで約1分かかります。棚卸しデータそのものはNeon側（無料枠でも期限切れなく永続）に保存されているため、スリープしてもデータが消えることはありません。もし待ち時間が気になる場合は、Renderの有料プラン（Starter, 月7ドル〜）にアップグレードするとスリープしなくなります。

### コードを更新したいとき

GitHub上のファイルを直接編集する（該当ファイルを開いて鉛筆アイコンをクリック）か、
ファイルを差し替えて再アップロードし「Commit changes」すると、Renderが自動的に再デプロイします。

## 5. 基本的な使い方

1. 「設定」画面で作業者名を入力し、「棚卸しを開始」する
2. 「バーコード読取」でカメラを商品バーコードに向ける（読み取れない場合は手入力欄も利用可）
3. 商品情報が表示されたら棚卸数量を入力して「登録」
4. 自動的に次の読取画面へ戻るので、同じ流れを繰り返す
5. 「棚卸一覧」でこれまでの登録内容を確認・検索・修正
6. 「ダッシュボード」で進捗率・未棚卸商品を確認
7. すべて終わったら「棚卸結果」画面から「棚卸し確定」（確定後は原則編集不可。修正が必要な場合は各明細の「棚卸し修正」から理由付きで訂正）
8. 「棚卸結果」からCSV/Excelを出力

## 6. 商品マスターの一括登録

「商品マスター」→「一括登録」からCSV/Excelファイルをアップロードします。
テンプレートは画面内の「テンプレートExcel(.xlsx)をダウンロード」または「テンプレートCSVをダウンロード」から取得できます。

列: `JANコード, 商品名, 部門, 仕入単価, 売価, 棚卸対象(対象/対象外), 備考, 登録在庫数`

JANコードが既存の場合は上書き更新、部門名が未登録の場合は自動的に部門を新規作成します。
商品コードの入力欄はなく、内部的にはJANコードがそのまま商品コードとして使われます。

⚠ **JANコードの桁落ちに注意**: JANコードは13桁前後の長い数字のため、ExcelでCSVファイルを直接開いて
セルに入力すると、自動的に「4.9E+12」のような指数表記に変換され、そのまま保存すると元の桁数が
失われてしまうことがあります（一度失われると復元できません）。これを避けるため、
Excelテンプレート(.xlsx)はJANコードの列があらかじめ「文字列」書式に設定済みです。
できるだけこちらのテンプレートを使ってください。CSVテンプレートを使う場合は、JANコードの列を
先にExcelで「文字列（テキスト）」書式に変更してから入力してください。

## 7. 部門の管理

「設定」画面の「部門の管理」から、部門の新規追加・名前の変更・削除ができます。削除は、その部門を
使っている商品が1件でもあると「◯件の商品で使われているため削除できません」と表示され実行できません
（先に該当商品の部門を変更してください）。商品の新規登録・編集画面でも、部門欄の横の
「＋ 新しい部門を追加」からその場で部門を追加できます。

## 8. 設定できる項目

* 重複読取時の処理: 「加算」（既定）または「上書き」
* 異常値警告の倍率: 登録在庫数の何倍を超えたら確認ダイアログを出すか（既定5倍）

## 9. データ保存・バックアップ

* データはPostgreSQL(Neon)にリアルタイム保存されます（画面操作のたびに都度コミット）。
* バックアップ/障害復旧はNeon側の機能に委ねる構成です。Neonは自動バックアップ機能を持ちますが、
  プラン・保持期間の詳細はご利用時にNeonのダッシュボードでご確認ください。
* すべての登録・修正・削除操作は `operation_logs` テーブルに記録され、「設定」画面から確認できます。

## 10. 今後の拡張（POS・会計・販売管理連携）

* 全機能をREST API（`/api/...`）として実装しているため、他システムからも同じAPIで
  商品マスター参照・棚卸データ取得が可能です。
* 商品マスターに自社商品コード(`product_code`)とJANコード(`jan_code`)を分離して保持しているため、
  POSや会計システムとのコード連携がしやすい構造になっています。
* 将来的に、棚卸し確定時に会計システム向けの棚卸差異仕訳データを出力するAPIの追加を想定した設計です。

## 11. 既知の制約（デモ実装）

* ユーザー認証は簡易な「作業者名」入力のみです。複数拠点で使う場合は、本番導入時に
  ID/パスワードまたはSSO認証を追加することを推奨します。
* バーコード読取は [html5-qrcode](https://github.com/mebjas/html5-qrcode) をCDN経由で利用しています。
  社内ネットワークでCDNへのアクセスが制限されている場合は、ライブラリをローカルに同梱してください。
* Neon/Renderともに無料プランには利用量やスリープ等の制約があります。本格運用への移行を
  検討される際は、各サービスの最新の料金・制約をあらためてご確認ください。
